# Compact invoice review workspace

Invoice review uses normal browser scrolling, a slim sticky review header and an approximately equal two-column workspace. The source opens at Fit width with natural page height and device-pixel-aware rendering; Fit page remains optional. Selected tab content and actions contribute to page height, without independent vertical scrolling in the main panels. Smaller widths stack the panels. Expand keeps the selected page and returns focus and page position without replacing invoice edits.

Issues, Invoice details and Activity use real tab semantics and Arrow/Home/End keyboard navigation. The same mounted form remains present while switching tabs. Findings retain every server check and group them by prerequisite, identity/PO, amounts/lines, receipts, bank details, waiting and passed. Counts include only actual unresolved outcomes; informational and passed findings are not failures. Passed groups start collapsed. Missing extraction is explained as a source-review task, without asserting that the document omitted the value. Issue actions focus relevant fields, PO selection, lines and bank controls. Receipts can be recorded through the existing independent receipt dialog; history remains in procurement management.

The details tab keeps invoice fields, amounts/tax, editable multiline line descriptions, PO selection and explicit source confirmation. Editing invalidates the source checkbox; switching tabs does not. Evidence is available through Source disclosures rather than permanent quotations. The bottom action area separates Save & rerun from Approve and explains why approval is unavailable. Unsaved or stale edits disable approval. Bank source correction and external verification remain separate and retain their existing masking and server safeguards.

Activity contains factual reader/fallback information, processing stages, immutable approval/audit history, original extraction and saved-record JSON export. Vendor follow-up opens an editable copy-only dialog, excludes extraction-null/uncertain prerequisites from its business draft, and never sends messages. PDF and image previews use the existing PDFium/Pillow libraries through an authenticated selected-page endpoint. Page and bitmap handles are explicitly closed. Previous/Next exposes all pages; Fit width is the default, with deliberate zoom and Fit page available. Rendering preserves aspect ratio and requests device-pixel-aware resolution, capped at 3200 pixels per dimension. Open original and Download remain available. Raster previews do not offer native PDF text selection or search. Expand uses a separate dialog without replacing the form.

In-app navigation with edits offers Stay, Discard changes and leave, or Save and leave. A failed save retains the input and leaves the user in review. Browser unload uses its native unsaved-change warning. Queue search, status, grouping, page and outer scroll survive returning from a review. The active invoice refreshes serially every 2.5 seconds. Clean results update in place, retaining the document viewer, selected tab, disclosure state and page position. Unsaved edits are retained and marked stale with an explicit reload action; focused inputs are left mounted until focus leaves. Request fingerprints, run numbers and timestamps reject superseded reads. Navigation stops the timer; focus/connectivity restoration refreshes immediately, and temporary errors show a reconnecting notice with bounded backoff. Save, reference resolution, verification and approval reuse the same in-place renderer. Reload with a draft uses the same leave/save/discard decision. A stale server revision stays protected by the existing expected-run check. Full browser-level navigation and filesystem download handling still depend on the browser.

## Live update regression (November 2026)

The former folder poll compared invoice summary timestamps but only called `notifyReviewUpdate`: the complete invoice and its final fields/findings were never rendered. The worker already commits completed state, result and audit atomically, so no backend ordering change was needed. The active review now fetches the full invoice with cache bypass, 15-second request timeouts and 2.5-second serial polling; failures back off to at most 20 seconds. Polling continues after completion to receive later changes, including a completed response lacking a result. The ordinary queue poll skips the active review.

Checks: `node tests/review-live.cjs`, `node tests/review-ui.cjs`, `node tests/ui-render.cjs`, `node --check web/app.js` and `git diff --check` pass. Full Python regression: 75 passed, one existing scan OCR failure because native Tesseract is unavailable. The live regression covers completion, partial results, dirty/focused forms, serial requests, navigation cleanup, superseded revisions, network backoff/recovery and failed jobs.

Browser reproduction used the actual local application in Chrome and a disposable SQLite backend with a delayed reader (test process only): uploaded `samples/08_unknown_vendor.pdf` via HTTP, opened its review while Processing / Reading document, then observed automatic final identity, vendor matching status and real findings without browser reload or queue navigation. Extraction and decisions ran through the ordinary pipeline with local fallback; no cloud or Gemini verification is claimed. The browser check establishes the unattended completion case; additional failure/order/draft scenarios are covered by the focused harness rather than claimed as browser interactions.
